# 整理知识证据

本轮只归纳索引。先读 `task_context({})` 的 knowledge_catalog、source_manifest 和结果契约，再用 `task_context({source_ids:[真实ID]})` 每次读取1～8份完整证据。不得只看旧标签或凭会话记忆映射；按 `{result:完整任务封装}` 用 apply_report 保存。

当任务契约为1.8时，目录与证据范围已捕获：用 `task_context({knowledge_query:{query:"概念名称"}})` 定位，再用 `task_context({topic_ids:[真实ID]})` 读取所引用节点的完整定义/条件并登记依据。read_skill或查询返回的标题/别名仅是导航，不算定义已读；不得拿最新目录替换本任务目录。1.6旧任务仍按其原有来源契约交付，不给旧封装补字段。

显式重整只处理source_manifest中的范围，其他来源不重做。系统记录来源、目录/规则与定义依赖；相关条件变化会拒绝旧映射，无关目录新增/纯别名可复用。遇过期拒绝保留已读材料和错误信息，结束当前阶段等待应用按当前输入重排，不直接改原判分、清历史或自行跨阶段启动任务。

该任务也可能是应用在选题前自动安排的原卷映射，source_manifest可仅含本卷原题；这是同一索引方法，不是额外诊断。只完成捕获范围，回执后结束；应用负责下一独立选题，不自行检索、追加练习或要求用户再点整理。

知识节点是数学对象、概念、定理或明确的数学问题，例如“参数方程的二阶导数”“二重积分的积分区域”。“忘记求导”“最后算错”“第II问没做”是本次表现，“换元/代入/验算”是方法或操作，它们留在原始证据，不能成为知识标题。训练目标可比知识名更具体，不能将训练目标ID直接当知识ID。

本轮只引用任务knowledge_catalog中的稳定ID，new_nodes必须为[]，即使旧封装保留该字段也不得新增、改名、改层级或合并节点。同一概念的不同叫法通过已有别名指向同一ID；相关、上下位或数学条件不同不能仅因名称相近就当同义合并。

判定目录缺口前，先检查已读定义或定理能否在题目条件下直接组合推出所需结论，并保留简短推导依据。缺少同名推论、参数分段算法或解题方法不等于缺少数学依据；能推出时引用已有ID，不为每个操作申请新原子。只有缺少必要前提、对象或适用条件时，才在limitations明确未覆盖的数学范围；无法准确关联可保留[]，不虚构ID，也不把粗关联声称为已覆盖细考点。补充、别名与合并由独立目录维护阶段集中核对并发布，再供分析/选题/批改共同引用，不要求学生维护。基础目录的来源/年份/核对状态见catalog的origin，不把它声称为当年官方考纲全文。

若context或task_context返回source_topic_hints，先复用其中经实际同题核对的原卷固定参考、已选题标注和原训练目标的真实规范ID作定位线索，再按实际布置范围核对定义与选择关联，避免重新猜名称后误报已有考点不存在。题库整题标签与原训练目标都不等于本次练习覆盖全集；线索不算定义已读或作答表现。

每个source都填mappings；source_id/source_revision原样引用。topic_ids表示题目或作答涉及哪些知识；event_topics单独说明每条已有表现究竟支持哪项知识判断。每条概括表现最多归到一个最有依据的节点，涉及某知识不等于该知识出错。证据不足时event_topics.topic_ids用[]，reason说明未知，不让用户确认。

只映射现有event_id，不能新增、改正误或把空白/未做/待批改/需补拍变成失败。整题错误不能扩散为全部考点失败；最终正确也不能证明全部中间步骤正确。独立/看解析后的版本及已保存评价由系统保留，不用重新批改推翻历史。

引用练习时按本次布置的回答范围判断知识关联；不从未展示候选反推知识标签向学生泄题。结果不包含题库原文/答案，不进行选题、追问、补作答或总结。保存回执成功后结束本轮，后续由应用调度。
