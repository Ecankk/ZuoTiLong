# 前端设计规范

本文件是前端信息架构、术语和视觉规范的唯一维护入口；产品行为见[产品流程](paper-review-workflow.md)，接口与后端分层见[项目架构](backend-architecture.md)。当前为重构设计稿（2026-11-02），视觉数值在静态样稿确认后定稿。

## 设计原则

1. **以结果为中心**：用户看到哪道题错在哪、该练哪个考点、练得怎样；不展示AI执行过程、会话或任务机制。
2. **阅读优先**：题干、公式和原卷图是主角。渐变与玻璃效果只用于导航和浮层，阅读区保持纯白、高对比。
3. **始终有一个明确的下一步**：每个页面突出当前最该做的一件事。
4. **AI在后台自动推进**：不提供“连接/重试阶段”等操作；进度就地显示（如“做题龙正在分析第12题”），失败用日常语言说明并只给一个处理按钮。
5. **面向非计算机背景的用户**：界面不出现Codex、会话、CLI、散列、版本号、契约等开发概念。

## 信息架构

侧栏一级入口：

| 入口 | 内容 |
| --- | --- |
| 首页 | **待办**：待核对的题、待做练习、批改中、新的批改反馈；**建议**：首版按已有数据规则生成（如某考点有未做练习、某卷已分析未出练习、某考点连续出错），不调用AI |
| 试卷 | 试卷列表与上传（上传处说明：黑笔为考试作答、红笔为事后批改）；单卷页：概览（得分、正误分布、本卷薄弱考点→跳转练习）、逐题分析、本卷总结 |
| 练习 | 独立模块。分析产生的练习汇入此处，可切换“按考点 / 按试卷”显示；每个薄弱考点≤3题；在此完成看题、作答、提交、查看批改 |
| 考点 | 考点树与考点详情：定义与条件、关联题（已完成 / 全部题库）、我在该考点的做题情况 |
| 画像 | 可视化分析：成绩趋势、各科目/章节正确率、薄弱考点排行、练习完成与独立正确率 |
| 题库 | 浏览与筛选（数学一/二/三、年份、考点） |
| 设置 | 备考类别（数学一/二/三）、同类别真题模糊显示、笔迹约定、数据备份与恢复、关于 |

侧栏底部为后台任务指示：空闲时不显示；运行时显示一句当前进度（如“做题龙正在分析《2023 数学一》”，不显示题号或百分比），点开查看排队与失败项。

做题龙在后台自动连接，界面没有“连接”按钮。本机未安装或未登录Codex CLI时，显示明确的引导（如何安装/登录，链接到配置教程），而不是报错。

### 新手引导

首次打开时显示新手引导（分步浮层，可跳过，之后可在设置“使用说明”重新打开）：

1. **做题龙能做什么**：上传已做的试卷 → 逐题分析 → 针对薄弱考点的练习 → 拍照提交作答 → 批改与画像。
2. **准备AI服务**：做题龙使用Codex（需ChatGPT Plus等可用账号）进行分析和批改。按接口返回的可用状态实时显示“已就绪 / 未安装 / 未登录”，未就绪时给出安装、登录步骤和配置教程链接；可先跳过，之后在首页和后台任务指示处继续提示。
3. **备考类别**：选择数学一/二/三（写入偏好设置）。
4. **笔迹约定**：黑笔为考试作答，红笔为事后批改；照片可选择、拖入或粘贴。
5. **开始**：上传第一份试卷。

“Codex”字样只出现在新手引导、AI服务未就绪的提示和设置“使用说明”中；其他界面统一称“做题龙”。暂不做联网公告；版本更新说明待桌面封装时再定。

题号条按选择/填空/解答分组：题型取自试卷匹配到的题库真题；无法匹配时只按题号排列，不猜测。

从普通界面移除：局域网手机传图、资料包（考点目录/标注索引）导入导出、默认提示词编辑、模型与会话控制、修订历史。资料准备通过安装流程完成。

单题分析分三层，其余默认折叠：

1. **结论**：正误与一句话说明。
2. **对照**：本人作答与首个实质性错误并列。
3. **解法要点**：切入点、关键步骤。

折叠内容：可能原因、参考推导、题目结构。

## 术语

| 统一用语 | 替代 |
| --- | --- |
| 练习 | 检验题、针对性检验、补强练习、probe等 |
| 逐题分析 | 原卷解析、诊断、原卷与诊断 |
| 考点 | 原子考点、统一考点、考点目录（界面不出现“原子”） |
| 做题记录 | 证据、学习证据 |
| 具体对象（这次分析、这次批改） | 本轮 |
| 做题龙 | Agent、Codex、学习助手 |
| 数学一 / 数学二 / 数学三 | 数学1、math_type原值 |
| 试卷“第N题”，练习“第N道” | 混用的量词 |

单题分析的“对照”为逐步对照：左列“你写的”（做题龙从作答图转写成公式的步骤），右列“应该是”；首个错误标红、改正标绿、受其影响的后续步骤变灰。转写可能有误，旁边保留原卷切图供核对。

## 视觉规范（样稿确认后定稿）

窗口：桌面应用窗口可自由调整大小并支持最大化/全屏；内容区最小宽度960px，布局按960～2560宽度自适应。内容区随窗口拉伸，但阅读文本列限制最大宽度（约760px）以保证行长适中，宽屏下用多列（如原卷图与分析并排）利用空间。不做手机网页版；不提供局域网手机传图，作答照片通过选择文件、粘贴或拖入上传。

布局：左侧固定侧栏（品牌、导航、后台任务），右侧白色内容区独立滚动；卡片不透明、细描边加柔和阴影。渐变只在侧栏；玻璃效果只用于侧栏选中项、弹窗遮罩和浮层，不放在题目、公式和原卷图后面。

配色取自做题龙标识：

| 用途 | 值 |
| --- | --- |
| 主色（按钮、链接、选中） | 靛蓝 `#2b4c9b`，柔和底 `rgba(43,76,155,.10)` |
| 品牌强调（仅标识与品牌位） | 火焰橙 `#f26b2a`、金 `#f6c453` |
| 侧栏渐变（方案D） | 底：`linear-gradient(176deg, #fff6e6 0%, #ffe9d4 50%, #fdf0d0 100%)`；左上光晕：`radial-gradient(110% 42% at 0% 0%, rgba(246,196,83,.30), transparent 70%)`；右下回暖：`radial-gradient(90% 30% at 100% 100%, rgba(242,107,42,.08), transparent 70%)` |
| 文字四档 | `#1c2333` / `#3a4255` / `#6b7385` / `#9aa1b0` |
| 正确 | `#1f9d7a`，底 `#e3f5ef` |
| 有误 | `#d64561`，底 `#fbe7eb` |
| 部分正确 | `#d9901a`，底 `#fbf0dc` |
| 待核/未知 | `#8a90a0`，底 `#eef0f4` |

火焰橙红不用于状态，避免与“有误”混淆。

- 字体：`Inter, "Segoe UI", "PingFang SC", "Microsoft YaHei UI", sans-serif`，统计数字用等宽数字（tabular-nums）。界面文字15px，次要说明不小于13px；阅读正文（题干、解析、批改）16px、行高1.8；页标题24px，区块标题20/16px。
- 进行中（分析中、批改中）统一用主色；待核/未知用灰色；四种正误色只表示结果。
- 圆角4/8/12/16/999，卡片12；间距4px网格；阴影为内高光、近影、柔影三层。
- 动效：120/180/240ms，`cubic-bezier(.22,1,.36,1)`；弹性动效只用于导航选中项；尊重`prefers-reduced-motion`。
- 滚动条保留细的自绘样式，不隐藏；不使用滚动渐隐模糊条。
- 深色模式暂不做，设计变量预留主题切换（`<html data-theme>`）。

Hindsight（GPL-3.0）仅作设计参考，不复制其代码或样式原文。

## 技术栈

React 19 + TypeScript + Vite；CSS Modules + CSS变量；Radix Primitives（对话框、标签页、浮层、提示）；lucide-react图标；React Router 7；TanStack Query按资源获取和失效；ESLint + Prettier + Vitest。KaTeX继续离线使用。

## 后端依赖

读取接口、任务摘要与SSE见[前端接口](frontend-api.md)；写入（上传、提交作答、确认查看等）沿用旧接口。首页数据、逐题分析状态、练习结果、partial批改、逐步对照等缺口待下一批后端接口。

## 实施顺序

1. 本规范与静态样稿（首页、单题分析、练习）确认视觉方向。
2. 约定接口。
3. 按流程逐页实现：外壳与设计变量 → 试卷与分析 → 练习 → 考点 → 画像 → 题库 → 设置；在前端分支整体替换旧界面。
