# 开发验证选择

本文件维护开发验证的选择与停止条件，不维护项目状态，也不是每包必跑清单。人工操作见[体验清单](manual-test-checklist.md)。

## 默认流程

先明确本次结果、范围和完成条件，复用现有实现；迭代中运行受影响的已有检查。新增测试须对应真实缺陷、重要规则或具体回归风险。

本次需求实现、相称检查通过且没有相关阻塞就交付。只有新改动、新失败或具体未解风险才补验；普通修改不另建方案、报告、快照或散列清单。

## 何时运行什么

| 改动 | 默认验证 | 扩大条件 |
| --- | --- | --- |
| 文档/注释/Skill措辞 | 看本次差异与改动引用 | 真实运行行为改变才转入相应测试；不派模型或模拟公开克隆 |
| 文案/样式/只读展示 | 前端代码定稿后构建，查看受影响页面 | 公式、交互或状态变化才选对应测试，不遍历全站/多端 |
| 局部逻辑/局部写入 | 受影响模块的已有测试；缺陷加最小复现 | 改事务、重复提交边界时核对应失败/幂等；有SQL不等于全量 |
| 新功能/接口/工具 | 主要成功路径和重要失败边界，核真实调用方 | 公共契约跨模块改变才全量；需验证模型消费时用一个代表任务 |
| 数据库迁移/共享事务或调度 | 全量后端一次，加改变边界的定向验证 | 存储格式、路径或备份/恢复机制变化时做独立恢复演练 |
| 影响范围确实无法界定 | 说明具体依赖/不确定性，全量一次 | 按实际失败定位，不以抽象风险无限扩测 |
| 数学内容/提示行为 | 核受影响来源和推导，选代表样例 | 实际误判再增加样例，不自动重标全库 |
| 本地升级 | 等在途写任务结束，保留已有工作，核受影响接口 | 正式数据变更前备份；纯源码/UI升级不默认全表/全文件核验 |

用户明确要求全量时执行；否则只按表中触发条件。确需全量时安排在最终相关代码上跑一次，中间使用定向测试。相关实现与依赖未变的结果可以复用，纯文档不使代码测试失效。

测试写入用隔离数据，不制造个人学习记录。当前可重建的旧测试数据采用已确认的一次性迁移或隔离重建，不推动长期兼容；真实材料、正式作答和在途任务的身份/版本仍须保护。不要为优化测试顺手重构全套夹具。

## 常用入口

按受影响文件选择后端测试，例如：

    .\.venv\Scripts\python.exe -m unittest discover -s tests -p test_result_text_integrity.py -v

触发全量条件时：

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v

前端按需选择，例如公式变化：

    node --test tests/math_render.test.mjs
    npm --prefix web run build -- --outDir ../tmp/validation-dist

完整前端测试用npm --prefix web test，但不自动追加。已有环境直接使用，首次配置或依赖改变才安装。

自动测试按[测试目录](../tests/README.md)定位。旧的真实模型、固定试卷和旧协议验证脚本已[归档](../scripts/archive/README.md)，不再作为可运行的默认入口。覆盖审计只随明确覆盖任务运行，不随日常开发启动。

## 阶段性完整闭环

仅首次交付完整生命周期、跨阶段流程实质改变或用户明确要求整体体验时组织，不作为每个局部修改的前置。

用一个小样：上传已做卷 → 分析 → 少量选题 → 本人作答并批改 → 查看画像；生命周期实现后再接结束、留存和重启续做。不等待全库资料准备。

F01指功能实现，F02指这条路径及相关失败恢复，F03指真实数学/手写和本次有关迁移有依据。未实现阶段如实说明；不以测试条数替代数学或提分结论，也不让无关未知阻塞本包。

## 干净学习数据重测

仅用户要求或旧数据妨碍验证时准备。保留旧库和回切方式，独立目录复用通用资料，不复制个人报告/作答/画像/记忆/曝光或旧执行票据。

用一个代表样例核学习零起点和任务归属。存储/恢复机制未变时复用已有恢复依据，不直接删个人表，也不额外启动全库审计。

## 交付

回复及所属TODO简述本次变化、实际检查结果和具体限制即可。模型和本人体验只在确实需要时安排；已有用户指定审核/暂停点继续遵守，不额外增设批准环节。
