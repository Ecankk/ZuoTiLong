# 人工体验清单

这里只说明需要本人体验时怎么操作，不维护开发状态或每包验收门槛。当前要体验哪一段见本机TODO；实际能力见[项目说明](../README.md)。

## 首次安装后的一次体验

按[配置教程](setup.md)安装，用用户自备的S01题源和项目[通用资料包](../resources/shared/README.md)初始化空资料库；不要复制维护者的运行数据库。应能在考点树看到题库关联，个人已完成题目、试卷和画像证据仍为空。

随后只执行下面的U01–U04/U06一轮：一份已做卷、一道本人手写、查看反馈后手动总结，刷新或重启确认记录保留。模型登录和本人解答由用户完成；开发侧的安装/导入检查不代替这次实际体验。手动安装与Agent安装是两种入口，无需为两种入口重复做完整试卷。

## 双向关联审核（U06）

无需重传试卷、清数据或连接Codex，打开本地“考点树”：

| 操作 | 预期 |
| --- | --- |
| 搜索一个熟悉考点，切换“已完成题目／全部题库” | 同一目录，个人完成数与题库关联数分开；没有个人记录不表示薄弱 |
| 从考点浏览原题，再点原子标签 | 主要/辅助/必要前置标签清楚，回到对应规范考点 |
| 看一个父级，分页后刷新/返回 | 子考点题目合并去重，来源可分别打开，定位和页码保留 |

已归档试卷在试卷归档中，不计当前完成数。标注就绪与预留/是否适合本轮选题是不同判断。当前审核点是否结束只更新TODO。

## 需要完整学习体验时（U01–U04/U06）

用一份已做PDF和一道自然完成的本人手写即可；不为测试额外做整卷。

| 操作 | 预期 |
| --- | --- |
| 上传并切题（U01） | 题号、跨页区域、作答与批改内容完整，缺页/识别问题明确 |
| 抽看对题、错题和空白题（U02） | 有思路、关键步骤和注意事项；正确部分保留，首错有据，可能原因不冒充事实 |
| 看一个补强目标的1～2题（U03） | 练到原问题，数量克制，回答范围清楚，真题保护按设置生效 |
| 暂存手写，再明确提交（U04） | 上传本身不批改；提交后读取有序照片并反馈，接受有效不同解法 |
| 查看考点/画像，刷新或重启（U06） | 原记录可追溯且保留；未知、看解析或部分正确不变成独立成功或整章掌握 |

只反馈“步骤＋题号/考点＋不符合预期的地方”，无需补标签、修JSON或校全库。问题修复后只重测受影响步骤。

相同PDF重传通常打开已有卷，重新分析也可能复用OCR；它们不是首次导入测试。确需干净重测时使用新的个人工作区并复用通用库；旧工作区保留可回切，不自行删库。路径配置见[数据边界](backend-architecture.md#数据归属与存储)。合并新代码后照常运行start_mathlens.bat即会重启后台服务；需要强制重启时加`-Restart`。

## 后续能力的体验

- 结束/留存/续做实现后（U05）：留一道未做题，结束、重启、继续，确认仍是原题/照片/草稿，旧总结不变。
- 跨卷画像（N03）：自然加入下一份卷后，查看同一知识是否合并，后续表现能否调整关注。
- Desktop/LAN/跨机（U07/U08）：仅对应能力开发并需要体验时单独安排。

这些不是当前功能交付的自动附加任务。开发检查如何选择见[开发验收](full-loop-test-checklist.md)。
