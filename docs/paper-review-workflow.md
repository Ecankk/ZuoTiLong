# 试卷复习流程

本文件维护产品行为；当前已实现能力见[项目说明](../README.md)，任务操作见[Agent协议](agent-workflow.md)。目标流程不代表所有阶段已经实现。

## 最小有效复习

以一份已做试卷组织复习。用户上传材料、阅读分析、做少量练习并提交；Agent承担数学解释、归纳和选题，程序承担材料管理、阶段调度、确定性检索和保存。

不要求用户维护标签、逐项确认可能错因、修改JSON或通过必经聊天推进。所有可读原题都分析，但不为每道错题机械分配练习。

## 学习流程

上传已做试卷 → 本地切题与题库定位 → 用户核对题号后开始分析 → 逐题分析 → 归并补强目标 → 精选练习 → 上传作答并批改 → 总结与长期画像。

目标中的收尾是“结束本次复习”：保存本轮证据和总结，未做精选题保留为同一记录供下次继续。它不等于归档试卷或认定全部掌握。具体实现状态只看项目说明和TODO。

应用在结果保存、取得回执且远端任务成功结束后派发下一阶段；Agent每轮只执行当前任务。失败保留已有材料和结果，只重试相关阶段。

## 数学分析与批改

- 先独立核验解法，再检查学生步骤；参考答案用于交叉核对。
- 每题解释切入点、关键步骤、注意事项和相关考点。保留正确部分，定位首个实质性错误，区分方法、建模、公式、计算和最终处理。
- 最终答案错误不能证明整个方法错误，答案正确也不能掩盖中间错误；接受有效不同解法。
- 错误位置是观察，为什么出错是推测。原因未知不抹去有据的正误；材料不足只请求必要补拍，不让学生完善诊断。
- 默认黑色手写为考试作答、红色为事后批改，用户可修改约定。红色对勾和更正分别识别，事后答案不算独立正确。
- 空白保留未作答事实，可进入补强；不虚构首错、耗时、心态或能力缺陷。自己的作答、外部解析和事后批改分开。

照片和文字可以先暂存；明确提交后才形成作答并触发批改。批改按本次布置范围进行，未布置的小问不算漏做。

## 考点、题目与画像

| 数据 | 职责 |
| --- | --- |
| 考点树 | 统一的学科、章节、大考点和原子目录，维护稳定ID、定义、条件、别名和来源 |
| 题目知识与指纹 | 描述题目条件、目标、原子关联、解法和必要操作，不记录学生能力 |
| 个人学习证据与画像 | 关联具体试卷、作答、批改及提示/解析曝光，聚合长期表现 |

同一概念复用ID；相关、父子或条件不同的概念不凭近名合并。普通分析、选题、批改和知识整理只引用已有目录；新增、合并或更名由独立目录维护处理。方法、计算环节和可能错因不强造为知识节点。

题库逐题准备通用标注，进入默认补强池的题须材料可用、标注就绪且依赖有效。未标注或待核题可浏览，不冒充已核练习。确认同题可复用数学知识，不代表不同参考答案都正确。历年卷先核实际条件、目标、选项和图，匹配后复用题目知识，再独立分析本次作答。

考点与题目双向关联，共用一个目录，提供“已完成题目／全部题库”两视图。原卷和补强是来源标记；程序完成正反查、子树汇总、分页和确认同题去重，标签可返回考点。已完成要求明确作答和保存分析或有效批改；空白、暂存、待批改、需补材料不算完成。归档记录保留在试卷归档中。

题库关联数、个人完成数和掌握状态分开。无个人记录不等于薄弱，无题节点也无需强行配题。画像由有效证据聚合，可追溯、可重建；独立与受提示完成分开，后续表现自然调整判断，不把整题错误扩散到所有考点或用一次成功证明整章掌握。

## 少量选题与显示保护

同卷问题按考点、缺口和目标环节合并；一个目标可关联多道原题，一道练习也可覆盖多个目标。重点目标默认1～2题是预算，可为0。

程序按现有原子/子树和必要环节召回，处理材料版本、预留、历史与确认重复；Agent实际阅读候选，判断数学适配和训练价值。检索原卷、已选、已做题及指纹，减少同题或仅换数的低价值重复；有明确间隔复习目的时允许重选。

检索使用数学一、二、三统一题池，不设类别配额。数学类别用于出处、适用元数据和显示保护：本地题库直接浏览；针对性练习中当前备考类别按设置确认，其他类别直接显示，预留卷不选入。切换视图不解除练习保护，看题或看解析不算成功。

允许追加练习，保留原题和作答，不要求先做完全部旧题。没有合适题就留空，改善后不机械增加题量。题库更新不自动变成学生的新作业。

## 保存与后续复习

所选题的展示、作答和批改对应同一材料版本。题库更新不偷换已布置题；关键材料不清时说明具体缺口，保留作答。

总结聚合已保存证据，区分已批改、未做、待批改及未知；没有前后表现就不虚构改善，不覆盖原批改或核定分数。后来的新证据不改写旧总结快照。

结束与续做应复用原练习、照片、草稿和曝光，不复制题目或制造成功/失败事件。运行中或远端状态不明时沿现有任务状态处理，不另建会话。
