# MathLens 参考源码审查与最小诊断闭环

审查日期：2026-10-22。范围：本地源码、题库文件完整性、现有 MathLens 提取逻辑的隔离测试。

## 结论与本轮交付边界

六个参考仓库已浅克隆到 `F:/kaoyan/references`，与 MathLens 主仓库分开。完整来源、commit SHA、数据文件散列和实测结果见 [reference-audit-results.json](reference-audit-results.json)。

这些项目可以提供零件，没有一个经过本次审查能直接承担“整卷作答证据 → 错因假设 → 区分性检验 → 跨卷验证”的完整流程。当前 MathLens 也没有完成这一闭环。

本轮新增审查文档、可重复运行的审查脚本及结果文件；没有把六个应用拼接进产品，没有安装它们的云服务依赖，没有向第三方 AI 上传试卷，也没有修改用户数据库。下文的目标数据模型和流程是实施设计，不是已上线功能。

## 参考项目逐项判断

### 1. math-question-bank：作为外部题源接入，不能直接视为完整诊断题库

- 来源：https://github.com/justcodeit404/math-question-bank
- 重点源码：`schemas/question-v1.md`、四个题库的 `questions.json` / `quality-hold.json`、`scripts/source_mapping.py`。
- 有价值：稳定 UID、LaTeX 题干、选项、小问、来源页码、题图/答案图引用、疑问题目的隔离清单。
- 实际 JSON 共 **2,900 题**，不是 README 声称的 2,879；以固定版本数据统计为准。

| 本地数据集 | 实际条数 | 题图引用 / 缺失 | 答案图引用 / 缺失 |
| --- | ---: | ---: | ---: |
| 1000题 | 901 | 14 / 14 | 901 / 901 |
| 660题 | 660 | 645 / 645 | 660 / 660 |
| 880题 | 927 | 778 / 778 | 927 / 927 |
| 大学深埋 | 412 | 144 / 144 | 412 / 412 |

引用是否存在按各 `questions.json` 所在目录解析。非空 `answer` / `solution` 文本字段均为 0。缺少的题图中也包含题目截图，不能据此推定所有对应题目都无法阅读；但涉及必要几何图的题目不能在缺图时推荐。答案图片缺失意味着克隆本身没有提供可核对的解答，不能直接用于自动判分。

前三个数据集标题明确为数二，第四个为高数与线代。不能宣称覆盖数学一，尤其要补充概率统计及数学一专属内容。`source_mapping.py` 还依赖仓库外特定“资料/数学2/电子资料”路径；应改成用户本地资源映射，不要求用户复制成作者的目录结构。

上游 quality-hold 标记 4 条暂挂，其余“verified”是上游记录，不等于我们独立核验过题干、答案或资源完整性。接入必须同时检查资源与适用范围。仓库根目录没有 LICENSE，README 写“仅供个人学习使用”；采用外部本地导入，不把其题目和代码直接随 MathLens 再分发。

建议适配成本：低到中（JSON 接入）；补齐答案、题图和数学一覆盖的成本另计。只读导入保留 `source_repo/source_revision/source_uid`，重复导入不能覆盖个人练习记录。

### 2. error-notebook：参考批量导入与输出校验，不能照搬为自动扫描卷处理

- 来源：https://github.com/Jasmine-Coder-Dev/error-notebook （README 引用 SteveSunYifan/error-notebook，需保留上游署名链）
- MIT；重点源码：`demo/js/pdfimport.js`、`demo/js/app.js`、`server/prompts.py`、`src-tauri/src/api.rs`、`src-tauri/src/prompts.rs`。
- PDF 流程实际使用 PDF.js 的 `getTextContent()`，把每页所有文本项用空格连接，再用行首题号正则拆题；原有逐题换行/坐标会丢失，同一页多题存在漏切风险。`split-check` 是给模型已有文本列表，让其合并或拆分，不是版面坐标检测。
- Rust 版本另有图片 OCR 接口，调用配置好的视觉模型，返回纯文本；提示词允许公式用近似文本表达。不能据此保证数学一公式、手写步骤、红笔批改与题目边界识别质量。
- 适合借鉴：结构化 JSON 校验、批量任务、原件保留、失败提示。
- 不采用：把人工整理每题作为前置条件、把知识点次数统计当作错因诊断、强制用户再配置一套 AI API。

### 3. kaoyan-quiz：参考短交互复习，不承担诊断引擎

- 来源：https://github.com/roizenken-design/kaoyan-quiz
- MIT；重点源码：`app.js` 的 `reviewResult`、错题记录与复习队列；`scripts/smoke.js`。
- 有价值：隐藏答案、短测、自评、到期队列，减少用户操作。
- 原理是 localStorage 记录题目、用户标注错因、连对次数和下次复习时间。没有“竞争错因假设—验证证据”模型。
- 数学卷的烟雾测试把总分 **152** 写为期望值；测试还硬编码作者本机路径。不复用这些评分规则和测试环境，更不能照搬到数学一。
- 适配成本：低，只参考交互；题库内容许可与代码 MIT 分开核对。

### 4. cuoti-zhiku：参考可靠本地数据管理

- 来源：https://github.com/whz211417/cuoti-zhiku
- MIT；Tauri + React + Rust + SQLite。
- 重点源码：`src-tauri/src/services/ingest.rs`、`src-tauri/src/domain/review.rs`、`src-tauri/src/db/`。
- 有价值：原文件 SHA-256 去重、内容寻址保存、临时文件后原子落盘、字段版本检查、备份、复习事件记录。
- README 明确当前不内置 OCR，扫描 PDF 需要先 OCR 或手动补题干。它的整理流程不能作为我们的默认用户路径。
- 不为复用它而把现有 Python 后端重写成 Rust；参考数据约束与事件记录，成本低于整套移植。

### 5. Zerror：参考分阶段任务和局部失败恢复，限制直接复用

- 来源：https://github.com/worstwoof/Zerror
- 重点源码：`backend/app/services/analysis_jobs.py`、`ai_engine/llm_logic/diagnostic_chain.py`。
- 有价值：先返回 OCR 部分结果，再做较慢的解释任务；解释阶段失败可以保留 OCR 结果继续重试。
- 注意：当前任务表是内存 `_jobs`，不是跨重启持久化任务队列，不能直接满足我们的恢复要求。
- `diagnostic_chain.py` 的提示词明确：`mistake_diagnosis` 主要为兼容保留，前端不展示；没有错误答案/自述时返回空。该模块主要服务解题讲解，并非我们需要的原因验证系统。
- Flutter、PostgreSQL、COS、vivo 接口等依赖与单人本地应用不相称。仓库根目录未找到 LICENSE，不直接搬用代码；借鉴流程即可。

### 6. exam_classifier：参考批处理恢复，不套用分类目标

- 来源：https://github.com/AdamWang72/exam_classifier
- MIT；重点源码：`src/question_splitter.py`、`src/auto_ocr.py`、`src/pdf_parser.py`。
- 有价值：逐段拆题、OCR JSON 缓存、失败段缩小重试、检索候选后分类。
- 原目标为政治试题分类，不能推定可识别考研数学公式和手写推导。
- 源码中的 `_retry_chunk_halves` 只要一个半段成功就返回成功，可能掩盖另半段遗漏。我们的完成条件必须是所有页/区域都被解释，而不是请求成功或得到非空结果。
- 不将它的 API 配置与教材分类体系作为用户额外负担。

## 当前 MathLens 的实测缺口

运行：`python scripts/audit_references.py`。脚本只读参考文件，在工作区临时生成 ASCII 数字文本 PDF 并清理，不读取或写入个人 SQLite。

| 检查 | 期望 | 当前观察 |
| --- | --- | --- |
| 题内小数 | 两道题 1、2 | 被拆成 1、0、25、2 |
| 题内小问 | 两道题 1、2 | 被拆成 1、1、2、2 |
| 同页不同题区域 | 不同裁剪框 | 两题得到相同整页文本联合框 |
| 两页各一题 | 页范围 1–1、2–2 | 第一题范围变成 1–2 |

这 **4 项均未通过**。另外，原题后附加“只给出正根”的不同任务仍获得 0.96 匹配分，说明分数不是同题概率，不能自动认定原题与变式相同。

本机 PyMuPDF 为 1.26.5；未检测到 PaddleOCR，空白页试验返回 `paddleocr_not_installed`。当前 `requirements-ocr.txt` 实际安装的是 PyMuPDF，PaddleOCR 仅注释为可选依赖。PyMuPDF 文本抽取不是 OCR，文本页被写死为 0.98 的值也不是实测准确率。手写、公式、批改痕迹识别尚未验证。

本轮没有执行六个参考项目的完整应用测试或付费 AI 调用，没有真实批改卷的逐题标注基准，因此不报告 OCR 准确率、人工耗时或提分效果。此前“能运行/能导入”的验证不能证明产品已具备可靠的自动切题和诊断能力。

## 回到目标：由证据驱动的最小循环

### 用户应当经历的操作

1. 上传已经做完的试卷 PDF。后台识别重复文件、页序、题干、作答、批改和分值区域，显示真实任务状态。
2. 自动切分并匹配已知题目。只将影响判断的疑点送来确认，例如“这里写的是负号还是划线”；不要要求逐题检查 OCR 文本。
3. 显示本卷最优先处理的 1–3 个问题机制，并给出对应原卷截图证据。没有充分证据时显示“待验证”，而非“你粗心/基础差”。
4. 从现有题库抽取少量区分性检验任务，允许只回答入手思路、积分限、某一步变换，不要求重新做整题。
5. 根据检验结果缩小错因范围，给一条具体修正动作；下一份新卷自动寻找相同机制的再次表现，更新画像。

正确题也可纳入：只有记录暴露出绕路、猜测、非法步骤、过度耗时等证据时优先抽查，不能为了完善标签让用户每道正确题都再做一遍。

### 自动化的技术边界

- 保留 React/TypeScript 前端、Python 处理管线、SQLite、本地原文件。优先补处理能力，不再次大换框架。
- 文本页提取文字及坐标；扫描/混合页做版面识别和视觉读取。文字层存在不代表手写作答存在于文字层，必须检查渲染图。
- 题干、学生作答、批改痕迹、参考答案分别保留来源。原件不可变，提取结果可版本化重跑。
- 每道题支持多个页内区域，不用一个跨页 bbox 表示全部证据；裁剪图应能追溯到页码及归一化坐标。
- 题库同题命中可复用规范题干与标准答案，仍须识别本次原卷中的作答和批改。相似题不能直接套答案。
- 匹配先候选召回，再核对条件、公式、参数、所问对象、选项与图形。候选分和同题判定分开记录。
- 不必把每个手写符号都变成漂亮的 LaTeX 后才开始诊断；能定位证据、准确理解关键步骤即可。只有影响结论的不确定处才问用户。
- 每阶段落盘：文件散列 + 阶段 + 工具/模型/提示版本 + 输入版本决定缓存；失败可续跑，重跑不覆盖已确认笔记和个人练习。

### Codex 的介入约定（待实现，不是现有功能）

保留用户在资料工作目录打开 CLI 的使用方式。应用把待处理任务、必要页图/裁剪和最小背景写入任务包；Agent 通过本地命令领取任务并提交结构化结果。应用校验来源、结构和任务版本后写入 SQLite，网页刷新任务状态和诊断结果。不要让 Agent 任意改数据库，也不要把爬取终端输出当通信协议。

任务类型只保留 `segment_paper`、`analyze_attempt`、`select_probe`、`evaluate_probe` 四类；各阶段支持失败、重试和部分完成。没有正在运行的 Agent 时明确显示等待，不假装后台会自动调用 AI。

网页无需用户额外填写 API key，不代表 AI 完全离线：用户仍需可用的 CLI 模型服务；其视觉/文件能力和鉴权方式须在接入时单独实测。当前审查没有验证 Codex 的具体调用协议或可用模型，不能承诺仅打开终端就自动处理。

### 题目指纹与用户画像必须分开

| 对象 | 最少保存什么 | 为什么 |
| --- | --- | --- |
| 题目 | 来源 UID/版本、规范题干、适用范围、已核验答案及资源状态 | 提供可靠检索和去重基础 |
| 题目指纹 | 对象、条件、目标、解法阶段、所需微技能、易混淆条件、版本及证据 | 描述这道题要求什么，不写学生是否掌握 |
| 作答事件 | 试卷、题目、原卷区域、作答步骤、得失分证据、提示/答案暴露情况 | 同一题多次作答不覆盖，观察与推断分离 |
| 错因假设 | 首个可见偏离步骤、可能机制、支持/反对证据、状态 | 答错不能直接归因“计算差”，连锁错误不重复诊断 |
| 检验事件 | 区分哪些假设、选了哪道题/哪一步、作答、提示程度、评价依据 | 检验要能改变判断，不只是推荐同章题 |
| 个人画像 | 微技能×触发条件的证据汇总、待验证/已支持/有反例、最近迁移表现 | 可由事件重算，不用孤立的百分比雷达图 |

先按需积累微技能，不建庞大知识大纲；同义机制保留归并关系和版本，避免每次让 AI 创造不同名称而无法跨卷追踪。缺少时间信息就记未知，不能从错误结果推定心态或耗时。

### 例：二重积分出错，如何区分背后原因

可能的机制包括：不理解区域约束、换序时不会分段、上下限正确但积分计算出错。它们都可能表现为最终答案错误，推荐一道“二重积分题”本身没有区分度。

先查看原卷：如果区域与上下限已经正确，不再把“不会建系”列为主要假设。仍有歧义时从已有题中选择一个只要求列积分限的任务；通过后，提供已给定积分限的计算任务。这里的任务是对现有题目指定回答环节，保持原题条件，并记录改用的任务目标，不冒充原题完整作答。

结果例：区域判断通过、换序分段失败、给定积分限计算通过。画像更新为“换序时识别分段边界：有失败证据”，并保留证据数量与来源。下一卷同环节独立做对才增加迁移证据；刚看完解析做对不等于稳定掌握。若各环节都通过，保留原假设待查，结合用户自述再检查审题/检查习惯，不强行诊断成粗心。

## 实施顺序与验收

1. 修正现有切题、逐题区域、缺页检查和状态；建立真实试卷基准。整卷自动化是第一道门槛。
2. 做外部题库只读适配，暴露缺图/缺答案/范围缺口，先建立一小批可靠检验题；资料缺失不可静默推荐给用户。
3. 实现单道错题的证据—假设—检验闭环，再扩展跨卷画像。诊断和检索用同一套微技能标识。
4. 加入重复上传幂等、任务恢复、证据撤销/更正和画像重算，确保增量更新可信。

不以导入条数、AI 报告长度或漂亮图表作为验收标准。以下是建议的发布门槛，**不是本轮已达到的数据**：

- 用至少 10 份含不同来源、扫描/数字/混合页、批改与跨页题的真实已完成试卷验证；离线建一次基准，不能把标注责任转交日常使用者。
- 实际主动整理时间 P90 ≤ 2 分钟/卷；需处理的切分/文字确认题 ≤ 10%。统计机器等待时间另列，诊断短测属于学习时间，不与录入负担混为一谈。
- 所有检测到的缺页、缺题、不可读页都明确阻断“处理完成”；基准上不允许静默漏题。题目覆盖与区域正确性必须独立评分。
- 每个展示为已支持的错因必须能定位作答或检验证据；只由模型推断的原因保持待验证。
- 初始每个优先机制至多 1–3 个短检验，仍无法区分则保留不确定，不无限追加题目。
- 跨卷统计相同机制在“实际出现该考查机会”时的复发比例、独立成功证据数及对应失分；不把没考到当作进步，不把试卷难度差异当作能力变化。

如果达不到录入成本门槛，应收窄支持的卷型或重新选识别方案，并明确支持范围；不能要求用户无限校对来掩盖自动化不足。
